# Narrative of Weekly Accomplishment Activities
**Internship Journey: Development of the School Clinic Management System**  
**Duration:** 13 Weeks  

---

### Week 1: Data Gathering, Planning, and Web Mockup Design
During the first week of my On-the-Job Training (OJT), I initiated the critical groundwork for the development of the school's Clinic Management System. The primary focus of this week was data gathering, which involved conducting detailed interviews and consultations with the clinic’s medical staff, specifically the school nurse and the physician. The main goal was to understand their current day-to-day workflows, identify specific pain points in their manual record-keeping processes, and determine the exact requirements of the proposed digital system. I spent time observing how they register incoming patients, document daily consultations, manage medical logs, and track medicine inventory using traditional paper logbooks. 

After gathering sufficient information, I proceeded to formulate a detailed project plan. This plan outlined the project's scope, target objectives, key milestones, development stages, and an estimated timeline to ensure a systematic and structured implementation process. Following the planning phase, I shifted my attention to designing the user interface (UI) mockups. Using digital design tools, I crafted interactive web mockups to visualize the overall look and feel of the system. I designed layouts for the login page, the main administrative dashboard, patient registration forms, and consultation records. 

I paid close attention to user experience (UX) principles, ensuring that the navigation was intuitive, clean, and accessible for the clinic staff who might not be highly tech-savvy. I presented these initial design concepts to my OJT supervisor and the medical staff for feedback, which helped validate the layout and flow before writing any code. This initial phase was crucial because it established a solid blueprint for the database structure and user interface flow, reducing the risk of major design changes later in the development cycle. By the end of the week, I had a clear roadmap and approved wireframes, setting a positive momentum.

---

### Week 2: Implementation of Front-End and Back-End, Backup System, and Responsiveness
In the second week of my internship, I transitioned from planning to actual system development, focusing on implementing the front-end and back-end structures of the Clinic Management System. I began by setting up the local database using MySQL and creating tables for user authentication, patient profiles, and medical records. On the front-end, I translated the approved mockups into functional web pages using HTML5, CSS3, and JavaScript, while using PHP on the back-end to handle server-side logic and database connectivity. I implemented the core functionalities, including user registration, secure login, and the basic CRUD (Create, Read, Update, Delete) operations for patient records. 

Recognizing the vital importance of data preservation, I also developed a reliable backup and recovery feature. I wrote a script that automates the generation of database backups (SQL dumps) and set up a recovery mechanism that allows the system administrator to restore the database to a previous state in the event of hardware failure or data corruption. This was a critical step in ensuring the system's resilience and reliability. 

Furthermore, I dedicated a significant portion of this week to making the entire system fully responsive. I utilized CSS Media Queries and flexible layouts to ensure that the user interface scales seamlessly across various screen sizes. I tested the responsiveness on multiple devices, including desktop computers, tablets, and smartphones. This mobile-friendly design is essential because it allows medical personnel to access the system and update records on the go using their tablets or mobile phones during campus emergencies. By the end of the week, the fundamental architecture of the application was established, functioning properly on both the client and server sides, and providing a responsive user experience.

---

### Week 3: Feedback Implementation, Security Integration, and Calculation Automation
During the third week, I focused on refining the system based on user feedback, enhancing overall system security, and integrating automated calculations. I started the week by presenting the working prototype to my supervisor and the clinic staff to gather their initial suggestions. They requested minor modifications to the user interface, such as repositioning certain input fields on the consultation form and adding a shortcut to search for patients. I immediately implemented these layout adjustments to improve usability and streamline the data entry process.

Following the feedback implementation, I prioritized securing the web application. I implemented several crucial security measures, starting with password hashing using the bcrypt algorithm to protect user credentials. To protect the database from malicious exploits, I refactored the database interaction code to use prepared statements, effectively eliminating the risk of SQL injection. Additionally, I added Cross-Site Request Forgery (CSRF) protection tokens to all forms and established basic Role-Based Access Control (RBAC) to ensure that only authorized personnel (such as doctors and nurses) can access sensitive medical records, while restricting access for standard users.

Lastly, I integrated automation features to minimize manual errors and speed up the clinical workflow. I wrote JavaScript functions that automatically calculate a patient's age in real-time as soon as their date of birth is selected in the form. I also built a Body Mass Index (BMI) calculator that automatically computes and classifies the patient's BMI (e.g., underweight, normal, overweight) based on the height and weight values entered by the nurse. These automated features not only reduce the cognitive load on the medical staff but also ensure data consistency and accuracy across all patient records. By the end of this week, the system was significantly more secure, user-friendly, and computationally efficient.

---

### Week 4: API and AI Research and Custom Domain Configuration
The fourth week of my OJT was dedicated to technical research and network configuration, specifically investigating potential AI and API integrations and setting up a custom domain for the clinic system. I began by researching various Application Programming Interfaces (APIs) that could add value to the system. I explored SMS APIs like Twilio and Infobip to evaluate the feasibility of sending automated text notifications to students and employees for appointment reminders or health advisories. I also researched lightweight Artificial Intelligence (AI) solutions, such as basic diagnostic assistance tools or automated symptom classifiers, which could assist the clinic staff in preliminary screening. I documented my findings regarding API pricing, integration complexity, and performance to present to my supervisor for future expansion.

After completing the research, I focused on configuring a custom domain for the clinic system to transition it from a standard localhost setup to a more professional, easily accessible environment. I configured Apache Virtual Hosts on the local server to map the project folder to a custom local domain name (such as `clinic.local` or a customized hostname). I then modified the Windows hosts file on the server machine and configured the local DNS settings to resolve this custom domain within the campus network. This custom domain configuration was a crucial step because it allowed other computers on the same network to access the web application using a clean, readable URL instead of a raw IP address. This configuration improved the system's accessibility and laid the network foundation for multi-user access across different departments. By the end of the week, the system was ready to be accessed locally via a custom domain, making it feel much more like a polished, professional web application.

---

### Week 5: IT Week and Inventory Management Implementation
The fifth week of my OJT coincided with the department's annual IT Week, which required me to balance my development work with participation in various departmental events, seminars, and technical workshops. Despite the busy schedule of IT Week, I managed to allocate significant time to implement a critical module for the Clinic Management System: the Inventory Management System. This module was designed to systematically track the clinic’s assets, which are categorized into medicine, medical supplies, and medical equipment. 

For the medicine inventory, I developed features to monitor stock quantities, track batch numbers, and record expiration dates. I implemented an alert system that visually highlights medicines that are low in stock or nearing their expiration dates, helping the clinic staff avoid using expired items and manage restocking efficiently. For medical supplies (such as syringes, bandages, and alcohol), I created a simple stock-in and stock-out logging system to trace usage patterns. Lastly, for medical equipment (such as nebulizers, blood pressure monitors, and stethoscopes), I added tracking fields for equipment status, serial numbers, and maintenance schedules. 

To make the inventory module functional, I wrote database queries that automatically deduct medicine and supply stocks whenever they are prescribed to a patient during a consultation. This integration between the consultation module and the inventory module ensured that stock levels are updated in real-time without manual intervention. Balancing my participation in IT Week with the development of this complex inventory module was challenging, but it taught me valuable time management skills. By the end of the week, the clinic had a functioning inventory tracker, greatly reducing the risk of manual stock discrepancies and expired medication administration.

---

### Week 6: Network Setup, Stakeholder Presentation, Beta Testing, and Public Forms
The sixth week of my internship was highly active, involving physical network setup, stakeholder presentations, beta testing, and public form deployment. I began by setting up the local network infrastructure, which involved configuring the network router, assigning static IP addresses to the clinic's computers, and configuring firewall rules to ensure that authorized devices could access the hosted clinic system securely. I verified that the application was accessible from multiple devices, including desktop computers in the clinic and mobile devices connected to the campus Wi-Fi. 

Once the network was verified, I conducted a formal presentation and live demonstration of the Clinic Management System for the clinic's medical staff and the school principal. During this meeting, I explained the system's key modules, demonstrated the user workflows, and highlighted how the system solves their previous manual record-keeping challenges. The presentation was highly successful, and the principal expressed strong support for the system's deployment. 

Following the presentation, we launched a beta testing phase where the clinic staff began using the system under my supervision to input real data. This testing allowed us to evaluate the system in a real-world scenario and identify minor usability issues, which I immediately resolved. Finally, I set up a public-facing network segment and created a secure public online form. This form allows students and school employees to submit health declaration forms, request clinic appointments, or update their personal medical history. This public form was linked directly to the main database, allowing the clinic staff to view incoming requests in real-time, bridging the communication gap between the school community and the medical clinic. This successful integration marked a major milestone in transitioning the school's medical services online.

---

### Week 7: Medical Certificate Generator and Archive Data Migration
In the seventh week of my OJT, I focused on extending the system's features by creating a digital certificate generator for the doctor's role and continuing the database migration process by inputting old records. The certificate generator was a highly requested feature designed to automate the creation of medical certificates, referral slips, and clearance forms. I integrated a PDF generation library (such as TCPDF or FPDF) into the back-end, allowing doctors to generate official, formatted documents with a single click. The generator automatically pulls patient information, consultation details, and the doctor's diagnosis from the database, inserting them into a standardized template. I also designed a clean, print-friendly layout that aligns perfectly with the school's official stationery, saving the medical staff from writing certificates by hand and reducing transcription errors.

After completing the certificate generator, I shifted my focus to the long and meticulous task of data migration, which involved inputting historical patient data into the system. This data consisted of paper-based medical records, immunization logs, and past consultation histories of current students and employees. I carefully reviewed the physical files, checked for missing or illegible information, and manually encoded the data into the database. Ensuring data accuracy during this manual transfer was critical, so I verified each entry against its physical counterpart. Digitizing these old files is essential for building a comprehensive longitudinal medical history for each patient, which allows the clinic staff to see past diagnoses and treatments instantly during consultations. By the end of this week, I had successfully integrated the certificate generator and migrated a significant portion of the clinic's legacy records into the database, transforming dusty paper archives into a searchable digital repository.

---

### Week 8: Legacy Document Scanning and Batch Patient Data Entry
The eighth week of my internship was primarily dedicated to the extensive and crucial task of inputting legacy patient records and scanning paper files into the Clinic Management System. Building on the previous week's progress, I continued to systematically digitize the clinic's physical archive folders. This week's batch of records consisted of older student cohorts and long-term faculty members, which required extra care due to the volume of historical data. To streamline this process, I utilized a scanner to digitize physical documents, such as previous medical clearance forms, laboratory test results, and signed consent letters, and saved them as PDF files. 

I then used the file upload feature I had integrated into the patient profiles to link these scanned documents directly to each individual’s digital record. This approach ensured that the clinic staff could view both the structured digital data and the original scanned paper files side-by-side. During the data entry process, I faced challenges with inconsistent formatting in the older paper logs, such as different formats for dates and phone numbers. To address this, I established a standard data entry protocol and did manual sanitization before encoding the information. 

I also monitored the database server's performance to ensure that uploading large files did not slow down system response times, implementing basic image and file compression algorithms where necessary. By dedicating this week to archiving old files, I helped build a comprehensive electronic health record (EHR) database, ensuring that when the system goes live, it will contain a rich history of student health profiles. This data entry phase, although repetitive, highlighted the critical importance of data completeness, confidentiality, and integrity in clinical software systems.

---

### Week 9: Database Organising, Upload Auditing, and Data Entry Continuity
During the ninth week of my OJT, I continued with the bulk data entry of legacy medical records and historical files, while also focusing on optimizing the system to handle the increasing volume of data. As the database grew with thousands of patient entries and uploaded document attachments, I noticed that search queries and page load times were starting to slow down. To resolve this, I spent time analyzing the SQL queries in the search module and added appropriate database indexes to key columns, such as patient names, identification numbers, and consultation dates. This optimization drastically reduced search response times, enabling clinic staff to find patient records in milliseconds.

Alongside database tuning, I continued manually encoding paper archives into the system. I digitized years of student medical histories, focusing on chronic conditions, allergies, and vaccination details, which are critical for emergency treatments. I also reviewed the file system structure on the server to organize the uploaded scanned files into structured directories based on patient ID numbers, preventing file clutter and ensuring easy backup operations. 

Furthermore, I performed security audits on the uploaded files, verifying that access to the upload directories was restricted. I modified the `.htaccess` configuration to prevent direct URL access to the uploaded PDFs, ensuring that only authenticated medical personnel logged into the system could view the medical records. By the end of the week, I had successfully input another major batch of legacy files while ensuring the system remained fast, organized, and secure as the volume of medical data expanded. This phase highlighted the real-world challenges of data scaling and server resource management.

---

### Week 10: Alumni Record Digitization and Faculty LAN Cable Troubleshooting
In the tenth week of my internship, I divided my time between digitizing legacy medical files and assisting the institution’s IT department with physical network maintenance. The data entry work continued as I encoded the remaining archives of older alumni and faculty medical logs. By this stage, the process had become more efficient as I had developed keyboard shortcuts and macros to accelerate data entry, allowing me to complete data inputting tasks faster while maintaining high accuracy.

In addition to data entry, I gained hands-on experience in physical network infrastructure by helping resolve connectivity issues in the faculty offices. The faculty members were experiencing frequent network disconnections due to worn-out and messy network cabling. I worked alongside the school’s network administrator to organize, route, and clean up the local area network (LAN) cables. This physical task involved crimping RJ45 connectors, testing cable integrity using LAN testers, and replacing faulty Cat5e/Cat6 cables. We routed cables through walls and under desks to prevent physical damage and clutter, and organized the connection points at the main network switch. 

This networking task was highly beneficial because it allowed me to apply theoretical knowledge of networking in a practical setting. I learned how to troubleshoot physical layer network issues, manage cable runs, and ensure stable local connections. Combining software development (data entry) with hardware tasks (LAN cabling) gave me a well-rounded understanding of how the clinic system depends on both reliable software and robust physical network infrastructure to function across campus. By the end of the week, the faculty enjoyed a stable network connection, and the clinic database grew even more complete.

---

### Week 11: Finalizing Cohort Data Entry and System-Wide Debugging
The eleventh week of my OJT was focused on final data entry tasks and conducting a thorough system debugging phase to prepare the Clinic Management System for deployment. I processed the final batches of historical paper logs, ensuring that all student cohorts currently enrolled had complete health profiles in the database. With the data entry almost complete, I shifted my primary focus to identifying and fixing bugs, performance issues, and user interface glitches that had been reported during the beta testing phase.

I conducted rigorous debugging across all modules of the web application. I fixed session timeout issues that had occasionally locked out users during long data entry sessions. I resolved SQL query errors that occurred when handling special characters (such as apostrophes in names) by properly escaping inputs and using parameterized queries. On the front-end, I corrected layout rendering bugs in older browsers, ensuring consistent font sizes, button alignments, and table spacing across Google Chrome, Mozilla Firefox, and Microsoft Edge. 

I also resolved a critical bug in the medicine inventory module where stock counts occasionally went negative if multiple prescriptions were submitted simultaneously, implementing transactional database queries to handle concurrent operations safely. Additionally, I optimized JavaScript error handling to prevent UI scripts from failing silently. This intensive debugging process was highly rewarding as it allowed me to refine my problem-solving skills and write cleaner, more resilient code. By the end of the week, the application was stable, error-free, and displaying correctly on all tested platforms, giving me confidence in its production readiness. The system was now fully prepared for its final transition to a live web environment.

---

### Week 12: Record Verification, Scripted Data Validation, and Index Optimizations
During the twelfth week, I focused on finishing the data migration process and performing final optimizations on the database. I completed the inputting of the last remaining legacy files and medical charts from the physical archives. To ensure the integrity of the newly entered records, I developed and executed custom PHP data validation scripts. These scripts scanned the database tables for any formatting errors, duplicate patient profiles, missing field values, or logical inconsistencies—such as mismatched birthdates and ages. Any anomalies found were manually cross-checked with the original paper files and corrected, ensuring that the database was clean and accurate.

Following the data validation process, I performed advanced database index optimizations to maintain high-speed search performance. Since the database now contained thousands of student records, consultation logs, and inventory entries, optimizing the search queries was critical. I created composite indexes on frequently queried fields, such as patient name combined with status, and optimized the SQL queries in the dashboard statistics module. 

These adjustments minimized server resource usage and ensured that the dashboard charts and tables loaded instantly. I also conducted load testing on the database to verify that it could handle multiple concurrent queries without bottlenecking. Digitizing the final files and running these database optimizations ensured that the system was not only complete in terms of historical data but also highly performant and reliable for daily use. By the end of the week, the clinic system had a fully digitized, optimized, and validated database ready for live deployment. The transition from paper-based operations to a modern, electronic system was officially ready to be finalized.

---

### Week 13: Final Layout Adjustments, Web Server Deployment, and Complete User Training
The thirteenth and final week of my OJT was marked by system adjustments, deployment, and final user training. I began the week by completing the absolute last entries of data migration and fine-tuning the system’s layout. Based on final feedback from the school nurse, I made minor CSS adjustments to improve the contrast of buttons, refined dashboard typography, and adjusted form alignments to make the interface even more clean and professional. 

Following these adjustments, I took the major step of upgrading the system from a local development environment to a live web application. I set up the web hosting server, created the production database, and uploaded all application files. I configured the security certificates (SSL) to ensure secure HTTPS connections and pointed the custom domain to the live server. This deployment allowed the system to be accessed via the web from any authorized device connected to the internet, officially transitioning the clinic system into a live web application.

To conclude my internship, I conducted a full, comprehensive system demonstration and training session for all user roles, including school administrators, doctors, nurses, and faculty representatives. I walked them through their respective dashboards, showed them how to register patients, log consultations, generate medical certificates, track inventory, and view reports. I also distributed a user manual and answered technical questions regarding system maintenance, data backups, and user management. The feedback was overwhelmingly positive, with users praising the system's speed, simplicity, and visual design. Implementing this web application and conducting this final handover was a proud moment that successfully concluded my 13-week OJT journey, providing the school with a modern tool that will improve health services for years to come.
